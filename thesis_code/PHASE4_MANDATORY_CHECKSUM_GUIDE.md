# Phase 4 — Mandatory checksum verification and reconstruction

**Scope:** PCA and nonlinear autoencoder only, on a raw or Phase-3-selected wide clinical CSV. No FIDDLE, no prediction model, no patient split.

## Why reconstruct?

PCA and autoencoders create **lossy** representations. The hospital sends reduced coordinates, a matching decoder, a packed missingness mask and the fields kept exact. The university **must reconstruct** to assess fidelity: RMSE/MAE of measured values, missingness preservation, IDs/time/labels and any retained clinical fields. This happens **in memory on every Phase 4 experiment**. Storing `*_reconstructed.csv` is optional (`--write-reconstructed`), because it can consume substantial disk space.

## Mandatory SHA-256 integrity verification

Every outgoing `.npz` gets a `.npz.sha256` companion file containing the digest of the **exact serialized NPZ bytes** and its basename. The gzip baseline also gets `source_csv_gzip6.csv.gz.sha256`, and its decompressed contents are checked against the original CSV SHA-256.

Before the receiver opens an NPZ, the code checks its checksum. A missing checksum, malformed entry, mismatched filename, or checksum mismatch produces a **hard error**. There is **no unverified reconstruction mode**. By default the receiver looks for `PAYLOAD.npz.sha256` alongside `PAYLOAD.npz`; use `--checksum-file` only if the verified manifest is stored elsewhere. Do not confuse the source CSV's SHA-256 with the NPZ's SHA-256: lossy representations have different file contents.

**Security caveat:** SHA-256 detects corruption and unintentional changes. If an attacker could modify both the payload and its `.sha256` file, the checksum alone would not authenticate the sender. Use a trusted channel (such as authenticated SSH/SCP) or a signed manifest for an adversarial security threat model.

## Hospital/development run

```bash
python 04_dimensionality_reduction.py \
  sepsis_1000_raw.csv \
  --methods pca autoencoder \
  --k 2 4 8 \
  --ae-max-iter 80 \
  --output-dir output/sepsis2019/phase4_dev
```

All runs generate, in one timestamped directory:

- `pca_k2_transfer_payload.npz` and `pca_k2_transfer_payload.npz.sha256` (similarly for other method/k combinations)
- `source_csv_gzip6.csv.gz` and `source_csv_gzip6.csv.gz.sha256`
- `phase4_comparison.csv`, `phase4_per_feature_reconstruction.csv`, and `phase4_metadata.json`

`phase4_comparison.csv` records `receiver_checksum_verified`, `checksum_filename`, `checksum_bytes`, `transmitted_total_bytes`, and `receiver_checksum_verification_seconds`. Simulated transfer times now include the checksum-file bytes. Real SSH/SCP transfer timing is a separate benchmark.

The output still includes reconstruction errors measured on originally observed clinical entries; features removed in Phase 3 cannot be reconstructed.

## University receiver — checksum mandatory

Transfer **both** the NPZ and its checksum file to the university (preferably over authenticated SSH/SCP). Then run:

```bash
python 04_dimensionality_reduction.py \
  --reconstruct-bundle received/pca_k4_transfer_payload.npz \
  --reconstructed-output received/pca_k4_reconstructed.csv
```

The receiver **automatically loads** `received/pca_k4_transfer_payload.npz.sha256` and refuses to proceed if it is absent or wrong. If the trusted checksum is saved in a different location, use:

```bash
python 04_dimensionality_reduction.py \
  --reconstruct-bundle received/pca_k4_transfer_payload.npz \
  --checksum-file manifests/pca_k4_transfer_payload.npz.sha256 \
  --reconstructed-output received/pca_k4_reconstructed.csv
```

### For payloads generated by the *previous* version

The old Phase 4 output created an NPZ and recorded its SHA-256 in `phase4_comparison.csv`, but did not write `.sha256` sidecars. To make the old payloads compatible with the new receiver, generate companion checksums **at the original sender location**, using **trusted unmodified payloads**:

```bash
cd path/to/old/phase4_run
for f in *_transfer_payload.npz; do
  sha256sum "$f" > "$f.sha256"
done
```

Compare the resulting hashes to the stored values in `phase4_comparison.csv` before relying on them. Do not generate a new checksum from potentially corrupted data after transmission; that would defeat the purpose of verification.

## Verified checks

The updated script was syntax-checked and run on a 1,200-row clinical CSV sample with PCA and autoencoder (k=2). It successfully reconstructed a valid payload, preserved missingness and passthrough fields, and **rejected** both a byte-corrupted payload and a missing-checksum case. The full 20,336-patient experiment has not yet been performed with these changes.
